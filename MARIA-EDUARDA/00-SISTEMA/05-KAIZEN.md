# Kaizen — pequenas melhorias contínuas

Kaizen significa buscar melhorias pequenas e úteis ao longo do tempo. Nesta biblioteca, registre somente aprendizados reais. Não crie trabalho artificial para parecer produtivo.

## Fluxo

```text
CONVERSA
→ APRENDIZADO
→ CLASSIFICAÇÃO
→ OWNER
→ REGISTRO
→ CONEXÃO
→ PEQUENA MELHORIA
→ NEXT_CURSOR
```

## Quando #KAIZEN for acionado

1. Identifique o que foi aprendido.
2. Verifique se o conhecimento já existe.
3. Localize o owner semântico.
4. Preserve a informação útil e a fonte, quando houver.
5. Proponha ou faça apenas o menor avanço solicitado.
6. Conecte notas quando houver uma relação real.
7. Atualize o checkpoint somente quando o estado mudar de forma relevante.

Se nada novo foi aprendido, diga isso brevemente. Não repita o mesmo aprendizado em várias notas.

## Integração com Michelin 3 Estrelas

O Michelin fornece os três critérios de qualidade usados neste núcleo. O Kaizen identifica o aprendizado real e o menor avanço após a aplicação e a prova.

```text
INTENÇÃO
→ ⭐ CONSTRUIR
→ ⭐⭐ INTEGRAR
→ ⭐⭐⭐ PROVAR
→ KAIZEN: APRENDIZADO REAL
→ NEXT_CURSOR
```

Não conceda estrelas sem evidência. Se o resultado ainda não foi verificado, use `UNKNOWN` ou indique a etapa pendente. Não crie uma segunda memória ou um fluxo paralelo.

Consulte o [protocolo Michelin](08-MICHELIN-3-ESTRELAS.md).

## Formato interno e fala humana

Os campos KAIZEN, DELTA e PRÓXIMO PASSO são para registro interno. Na conversa da Duda, dizer naturalmente o que foi aprendido e, quando útil, uma ideia opcional para depois, sem cobrança.
